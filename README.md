# Power TBM 자동 시연 홈페이지

## 2026-10-16 재생 중 튕김·끊김 수정 (v100)

- 캐시 업데이트 때 재생 중인 창을 강제로 새로고침하던 동작을 제거했습니다.
- 온라인 영상은 브라우저의 스트리밍·Range 요청을 그대로 사용합니다. 파일 전체를 JavaScript 메모리에 읽거나 재생 응답을 복제해 캐시 저장이 끝날 때까지 기다리지 않습니다. 오프라인 영상은 Blob 범위로 응답합니다.
- TV에서 버퍼링이 길어져도 `load()`로 다운로드를 다시 시작하지 않습니다. 데이터가 있는 영상이 의도치 않게 일시정지된 경우에만 재생을 다시 요청합니다.
- TV는 현재 장면의 축소 이미지만 읽고 이전 장면의 이미지 소스를 해제합니다. 장면별 이미지 픽셀 용량은 최대 66.4 MiB RGBA로 제한했습니다(실제 기기 메모리 측정값은 아님). PC 원본 이미지와 안전-4컷 원본 영상은 유지합니다.
- TV 오프라인 파일은 34.1 MiB이며 한 번에 한 파일씩 저장합니다. PC용 별도 음성·배경영상은 TV에서 미리 다운로드하지 않습니다.
- 수정: `app.js`, `tv-compat.js`, `index.html`, `safety4cut.js`, `pwa.js`, `sw.js`, 관련 테스트. 추가: `assets/tv-v100/images/`, `scripts/build-tv-images.py`, `tests/verify-streaming.mjs`. 원본 이미지 변경 후 Python/Pillow로 `python3 scripts/build-tv-images.py`를 실행합니다.

검증: `node tests/tv-playback.test.cjs`, `node tests/verify-streaming.mjs`, `node tests/verify-pwa.mjs`, `node tests/verify-original-video.mjs`, `node tests/verify-recorder.mjs`, `node tests/verify-subtitle-modes.mjs`. 버퍼링 중 재로드·캐시 업그레이드 중 새로고침·영상 전체 메모리 복사를 수정 전 실패하는 검사로 재현했습니다. 실제 webOS 장치의 디코더·스피커 출력과 장시간 반복 재생은 별도 확인이 필요합니다.

- webOS / Web0S / NetCast / LG Browser / SmartTV는 호환 모드로 진입합니다. PC에서 모의 확인은 `?tv=1`, 호환 모드를 끄려면 `?tv=0`을 사용합니다.
- 호환 모드는 하나의 video 요소로 영상·내레이션·배경음을 재생합니다. 오프닝과 골든룰스 영상은 TV용 파일에 합쳤으며, 안전-4컷 결과는 기존 `09-ai-example-v84.mp4`의 원본 영상과 소리를 끝까지 사용합니다.
- 스탠바이미에서는 시작 버튼의 짧은 효과 영상을 생략하고 오프닝으로 이동합니다. 배경은 해당 영상의 정지 이미지를 표시하고, 장면 동기화는 최대 20Hz로 제한합니다. 실제 영상은 30fps이며 기존 소리/무음 시작 선택을 유지합니다.
- 의도한 일시정지·숨김 상태를 제외하고 8초간 진행이 멈추면 최대 두 번 복구를 시도합니다. 계속 실패하면 해당 장면에서 멈추며 소리 버튼 또는 중앙 터치로 재시도할 수 있습니다.
- 변경 파일: `app.js`, `index.html`, `safety4cut.js`, `subtitles.js`, `demo-recorder-v81.js`, `sw.js`. 추가 파일: `tv-compat.js`, `tv-compat.css`, `assets/tv-v99/`, `scripts/build-tv-media.py` 및 관련 테스트.
- 서비스워커 캐시는 v99로 갱신했습니다. TV 파일을 오프라인 캐시에 포함하고, 반복 재생에서 메모리에 보관하는 미디어 Range 버퍼는 최대 3개로 제한합니다.
- 음성·영상 원본을 교체하면 `python3 scripts/build-tv-media.py`로 TV용 미디어를 다시 만드세요. Python 3와 ffmpeg가 필요하며 배경음 라이선스는 `assets/audio/BGM_CREDITS.txt`입니다.

검증: TV 모의 DOM/미디어 테스트, 기존 원본 영상·터치·녹화·자막·PWA 테스트와 H.264/AAC 스트림·디코딩 검사. 실행 브라우저 도구를 사용할 수 없어 실제 화면 배치·스피커 출력·webOS 성능은 확인하지 못했습니다. 실제 스탠바이미에서 전체 시연 1회와 골든룰스·안전-4컷·일시정지를 확인해야 합니다.

## 2026-10-06 PC 녹화·내부 영상 수정 (v92)

- 녹화를 시작하기 전에 배경·오프닝·골든룰스11·4컷 영상의 첫 프레임을 읽을 수 있는지 확인합니다. 읽기 실패 시 녹화를 시작하지 않고 안내합니다.
- 녹화 중에는 동작 줄이기·데이터 절약 설정 때문에 영상과 시연 장면이 정지하지 않도록 합니다. 종료 후 일반 재생 설정을 복원합니다.
- 4컷 완성 영상은 화면의 `<video>` 하나로 원본 영상과 음성을 함께 재생합니다. 자막·일시정지·재개도 같은 시간을 따르며, 재생 실패 시 소개 화면으로 무음 반복하지 않습니다. 원본 MP4 바이트는 그대로입니다.
- 골든룰스11의 일시적인 재생 취소는 다시 시도할 수 있습니다. 녹화 중 영상·음성이 재생 오류를 내면 그 시점까지 저장하고 오류를 안내합니다.
- 녹화 형식은 H.264/AAC를 명시한 MP4 우선입니다. AAC 녹화가 불가능하면 WebM/Opus로 저장하고 안내합니다. 코덱을 지정하지 않은 MP4를 선택하지 않습니다.
- 지원 브라우저에서는 공유된 오디오의 실제 신호를 검사해 무음 녹화에 경고를 표시합니다. 마이크는 사용하지 않습니다.
- 수정 파일: `app.js`, `safety4cut.js`, `subtitles.js`, `demo-recorder-v81.js`, `styles.css`, `index.html`, `sw.js`, 관련 테스트와 이 문서. 배포할 때 실행 파일 7개를 함께 반영해야 합니다.

검사: `node tests/verify-original-video.mjs`, `node tests/verify-recorder.mjs`, `node tests/verify-subtitle-modes.mjs`, `node tests/verify-pwa.mjs` 및 `git diff --check` 통과. PWA 검사는 캐시 98개, 미디어 16개, 오프라인·Range 응답을 확인합니다. 녹화 검사는 모의 MediaRecorder 환경이며 실제 인코더 검사는 아닙니다.

실제 PC 확인 필요: Chrome/Edge에서 현재 탭과 탭 오디오를 공유해 전체 시연을 녹화하고, 배경 움직임·골든룰스11·4컷 전체 영상·마지막 장면과 저장 파일의 소리를 확인합니다. Windows 기본 재생기, iPad/Safari의 실제 동작은 별도 확인이 필요합니다. 이번 실행 환경에는 브라우저 실행 도구가 없고 브라우저 설치도 실패해 실제 화면 녹화 검증은 완료하지 못했습니다. 기존에 저장한 무음 파일은 제공되지 않아 해당 파일의 코덱이나 오디오 트랙 유무는 확인하지 않았습니다.

Power TBM 앱의 실제 화면 흐름을 한 페이지에서 자동 시연하는 반응형 정적 웹사이트입니다.

- 화면 구성: 자동 시연 한 페이지
- 개발자 표기: `개발자 : 안산지사 최재혁 차장`
- 시연 범위: 기상정보, TBM 회의록, 안전가이드·현장도구
- 재생 기능: 전체 자동시연, 구간 선택, 일시정지, 다시보기, 음성·배경음
- 현장 배경영상: 기상·도면 검토·현장작업·응급의료·마무리 장면을 구간별로 무음 재생하며, 26~100초 길이의 원본·몽타주로 짧은 반복 전환을 제거
- 회의 배경: 59.5초 영상을 1.5초 교차 전환으로 100초까지 자연스럽게 연장해 시공관리책임자 서명과 PDF 확인 구간에서도 계속 재생
- 현장도구 배경: 고소차 전선 보수·변전설비 점검·지게차가 움직이는 공사 현장을 약 54초 영상으로 연결해 도구 시나리오 구간을 역동적으로 표현
- 업데이트 안정성: 배경영상 파일명을 버전별로 분리하고 새 서비스워커 활성화 시 화면을 자동 갱신해 이전 영상 캐시가 다시 나타나지 않도록 처리
- 첫 장면: 손가락 시작 화면의 우측 하단에 `소리로 재생`과 `무음으로 재생`을 바로 표시하며, 원하는 모드를 한 번 누르면 3.5초 버튼 영상과 기존 오프닝이 이어지고 전체 반복도 선택한 모드를 유지한 채 이 장면부터 다시 시작
- 오프닝 배경: 손가락 시작 화면은 유지하고, 그 다음 오프닝 장면에 송전선로와 푸른 번개 배경 및 은은한 번개 섬광 효과를 표시
- 워터마크 가독성: 기상·회의·현장도구·응급·마무리 배경영상의 밝기와 투명 덮개 농도를 조정해 현장 장면을 더 쉽게 식별
- 전시용 가독성: 오프닝 이후 기상·회의록·안전·현장도구·마무리의 제목, 설명, 단계표시를 아이패드 가로 전시 화면에서도 멀리서 읽히는 크기로 확대
- 골든룰스11: 메뉴 진입 직후 Rule.1 안전영상이 휴대폰 화면 안에서 무음 자동재생
- 부드러운 재생: 모바일용 짧은 동작 장면, 하드웨어 자연 재생, 중복 화면 동기화 제거
- 최신 화면 교체: 홈 기상특보 접힘·펼침, TBM 회의록·체크리스트 통합 메뉴
- 날씨 강조선: 각 날씨 카드의 실제 외곽선에 맞춰 정렬하고 태풍정보는 5개 링크만 개별 강조
- 회의록 진입: 날씨 시연과 동일한 맑은 홈 화면에서 TBM 회의록으로 이동
- 원격서명 안내: 서명 화면 진입 직후 김일용 전용 QR을 먼저 표시하고, QR 종료 뒤 서명란에도 `김일용` 전체 이름을 반영
- 회의록 결과: PDF 화면의 작업자 이름과 서명을 김일용으로 표시
- AI 검토 확인: 결과 화면 전체 칸을 노란 선으로 맞추고, 손가락을 위로 미는 동작과 화면 스크롤을 같은 순간에 동기화한 뒤 아래쪽 확인 버튼을 정확히 누르도록 정렬
- 서명 순서: `QR → 김일용 서명 완료 → 최재혁 직접서명 → 두 서명 완료` 순서로 표시
- 현장도구 강조 순서: `공지사항 → 음성메모 → 거리뷰 → 비상연락망 → 응급의료시설`로 표시하고, 응급의료시설은 여성 내레이션 시작과 동시에 강조

## 실행

설치와 오프라인 기능은 HTTPS 배포 주소 또는 `localhost`에서 작동합니다. 단순히 `index.html` 파일을 직접 여는 방식(`file://`)에서는 서비스워커가 등록되지 않습니다. 로컬 확인은 이 폴더에서 간단한 서버를 실행합니다.

```bash
python3 -m http.server 8000
```

그다음 브라우저에서 `http://localhost:8000`을 엽니다.

정적 사이트이므로 폴더 전체를 GitHub 저장소에 올린 뒤 Vercel에서 Framework Preset을 `Other`로 선택하고 Build Command 없이 배포할 수 있습니다.

## 휴대기기 설치와 오프라인 사용

- Android: Chrome에서 홈페이지를 연 뒤 메뉴의 `앱 설치` 또는 `홈 화면에 추가`를 선택합니다.
- iPhone·iPad: Safari에서 홈페이지를 연 뒤 `공유` → `홈 화면에 추가`를 선택합니다.
- 설치 전 첫 접속은 인터넷이 연결된 상태에서 완료해야 화면·글꼴·내레이션·배경음·영상을 기기에 저장할 수 있습니다.
- 설치가 끝난 뒤에는 인터넷이 없어도 버튼 클릭 장면, 전체 자동 시연과 모든 소리, 골든룰스11 및 현장 배경영상이 재생됩니다.
- 앱을 새로 실행하면 우측 하단의 `소리로 재생` 또는 `무음으로 재생`을 한 번 눌러 바로 시작합니다.

## 주요 파일

- `index.html` — 한 페이지 시연 화면과 개발자 표기
- `styles.css` — PC·태블릿·모바일 반응형 레이아웃

- 골든룰스11 영상은 실제 시연 구간에 필요한 7초 동작 장면만 사용해 설치 용량과 디코딩 부담을 줄였습니다.
- 현장도구 배경은 절연스틱 표준시공 영상의 4분 13초 이후 작업 장면을 원본과 동일한 1배속·30fps로 100초 동안 사용하며, 제목·설명 자막과 영상 로고는 확대 구도로 모두 제외했습니다.
- 응급의료 배경은 창원성산소방서 119 구급차 출동 영상으로 교체하고, 우측 상단 편집기 표시는 잘라낸 뒤 서명 구간 동안 움직임이 계속 이어지도록 100초 타임라인에 맞췄습니다.
- 마지막 멘트 배경은 `한국전력공사 TBM가이드`의 9분 5초부터 9분 11.37초까지를 정상 1배속·30fps로 사용하며, 글씨가 나타나기 직전 작업자 단체 화이팅 장면에서 재생을 멈추고 마지막 프레임을 유지합니다.
- 오프라인 미디어 구간 요청은 기기 메모리에서 재사용하고, 최초 오프라인 저장은 소규모 묶음으로 진행해 첫 실행 중 화면 끊김을 줄였습니다.
- 기존 설치본을 업데이트할 때는 온라인 상태에서 새 배포본을 한 번 연 뒤 앱을 완전히 닫았다가 다시 실행합니다.
- 화면 캡처를 교체할 때는 기존 파일명을 유지하면 코드 수정 없이 반영할 수 있습니다.
- 배경음 저작권 정보는 `assets/audio/BGM_CREDITS.txt`에서 확인할 수 있습니다.
- 배경영상 출처와 이용 조건은 `assets/background/ATTRIBUTION.md`에서 확인할 수 있습니다.

## v85 · 전체 음성 자막

- 하단 `자막 ON / OFF` 버튼으로 전체 내레이션 자막을 표시합니다. 기본 ON이며 브라우저에 선택을 저장합니다.
- 단어별 음성 시점에 맞춰 흰색 글씨가 노란색으로 바뀝니다. 음소거 중에도 표시되며 구간 이동·일시정지와 동기화됩니다.
- 최신 v84의 4컷 소개 음성과 원본 MP4 음성은 각각의 재생 시간에 맞춘 자막을 사용합니다. 음성 인식 기반 시간이므로 일부 발음에 미세한 차이가 있을 수 있습니다.
- 영상 자체에 포함된 글자는 자막 OFF로 사라지지 않습니다. 원본 미디어와 끝까지 재생하는 로직은 유지합니다.
- `subtitle-data.js`, `subtitles.js`, `subtitles.css`를 추가하고 PWA 캐시를 v85로 갱신했습니다.
- 확인: 기존 원본 영상 회귀검사, 오프라인 캐시·Range 응답 검사, Chromium의 ON/OFF 저장·음소거·소개/영상 자막 전환 및 반응형 표시. 실제 iPadOS Safari와 녹화 파일 출력은 별도 확인이 필요합니다.

## v86 · 말풍선과 기존 자막 효과 선택

- 우측 하단의 자막 표시 방식에서 `기존 자막 효과 / 말풍선 안내 / 자막 끄기`를 선택합니다.
- 기존 효과는 전체 대사와 흰색→노란색 강조를 그대로 유지합니다. 말풍선은 같은 음성 시점에 맞춘 짧은 안내를 화면 옆에 표시하고, 좁은 화면에서는 시연 화면 위에 배치합니다.
- 선택은 브라우저에 저장됩니다. 이전 ON/OFF 설정을 유지하며, 별도 선택이 없으면 기존 효과로 시작합니다.
- 기존 영상 및 음성, 단어별 타이밍 데이터는 변경하지 않았습니다.
- 확인: `node tests/verify-subtitle-modes.mjs`, `node tests/verify-original-video.mjs`, `node tests/verify-pwa.mjs` 통과. 이번 환경은 브라우저 실행 소켓 권한 및 권한 상승 정책 때문에 실제 화면 검증을 수행하지 못했습니다. iPad/휴대폰에서 말풍선 위치와 가림 여부는 확인이 필요합니다.


## v87 · 말풍선 전체 자막 교정

- 말풍선의 요약 문구를 제거하고 기존 전체 자막과 동일한 문구·시간 데이터를 사용합니다.
- 말풍선도 음성에 맞춰 문구가 차례로 바뀌며, 내용을 줄이거나 생략하지 않습니다.
- 선택 메뉴는 `기존 자막 효과 / 말풍선 자막 / 자막 끄기`입니다. 기존 하단의 흰색→노란색 강조와 선택 저장 기능은 유지합니다.
- 모든 구간의 말풍선 문구가 기존 자막과 일치하는지 검사했습니다. 브라우저 실행 권한 제한으로 실제 기기 화면 배치는 별도 확인이 필요합니다.
